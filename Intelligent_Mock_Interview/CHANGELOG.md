# Changelog — Intelligent Multimodal Mock Interview Assessment System

All notable modifications applied during the functionality refinement phase are documented below in beginner-friendly language.

---

## [1.1.0] - 2026-10-31

### 1. Fix 1: Controlled Employability Prediction & State Persistence
- **File Modified:** `frontend/app.py`
- **What Was Changed:** 
  - Removed the `or True` statement from the button evaluation condition (`if predict_btn:`).
  - Integrated Streamlit `session_state` (`st.session_state["employability_result"]`).
- **Beginner-Friendly Explanation:** 
  Previously, the code had a temporary debugging flag (`or True`) that caused the machine learning model to execute on page load with default slider values. Now, the Gradient Boosting model only runs when the user explicitly clicks the **"Predict Employability"** button. The prediction, probability score, radar chart, and advice are safely stored in session memory so they stay on screen without re-triggering inference every time a slider is moved.

---

### 2. Fix 2: Multimodal Audio + Text Evaluation with Explainable Fusion
- **File Modified:** `frontend/app.py`
- **What Was Changed:**
  - Added an interview question selector and benchmark reference answer viewer to the Multimodal tab.
  - Added an explicit **"Evaluate Multimodal Response"** trigger button.
  - Connected the uploaded audio to the `CandidateAudioAnalyzer` (Librosa) and the candidate transcript to the `InterviewTextAssessor` (TF-IDF).
  - Implemented an explainable rule-based composite scoring formula:
    $$\text{Multimodal Score} = 0.50 \cdot \text{Text Quality} + 0.25 \cdot \text{Normalized Fluency} + 0.25 \cdot \text{Normalized Prosody}$$
  - Displayed both an **Integrated Score Card** and side-by-side **Acoustic & Textual breakdowns**.
- **Beginner-Friendly Explanation:** 
  Previously, uploading audio only showed audio metrics, ignoring what the candidate actually said. We now have an end-to-end evaluation: Librosa measures how smoothly the candidate spoke (pauses, rhythm, pitch), while the TF-IDF engine measures what they said (technical relevance and accuracy against the question). Because we do not have an aligned multimodal training dataset, we combine these scores using an honest, transparent percentage formula rather than claiming a fake neural network.

---

### 3. Fix 3: Dynamic Loading of Model Benchmark Metadata
- **File Modified:** `frontend/app.py`
- **What Was Changed:**
  - Removed the static hardcoded results list in Tab 4.
  - Dynamically parsed model comparison rows directly from `models/employability_model_meta.json`.
  - Formatted metrics into clear percentages and 4-decimal values, sorted by ROC-AUC descending.
- **Beginner-Friendly Explanation:** 
  Previously, the benchmark table contained manually entered numbers in the script. Now, the app reads directly from the saved JSON experiment log (`models/employability_model_meta.json`) generated by our training pipeline. If any model is re-trained in the future, the UI will automatically display the updated experimental numbers with zero code changes.
